# hostvitals

A read-only macOS agent CLI for host and process observations. Start with `hostvitals --help`, then `hostvitals doctor`; `hostvitals help all` opens the complete manual. Doctor inventories observation capabilities. `hostvitals now --seconds 3 --top 10` measures host CPU, memory and network, every user's processes, responsible App totals and eight rankings in one window. Other users' CPU, resident memory and network bytes are included without root; footprint reads that need elevation are explicitly skipped. `hostvitals memory <pid> [--top 15]` explains one Process's Footprint, region kinds, malloc zones and largest regions; `hostvitals memory --help` documents every output key and the size ranking.

Build locally with `cargo build --locked -p hostvitals` on macOS arm64 or x86_64. Stable Rust builds the binary; the pinned nightly runs the verification gate. `./gate.sh` is the same gate locally and in CI: format, Flux alone (no trusted or ignored functions), clippy, then nextest. The checker versions and nightly live in `Cargo.toml`; `./verify.sh` rejects mismatches with installation instructions. Install nextest with `brew install cargo-nextest`.

`hostvitals process <pid> [--seconds 3]` observes one Process: identity and responsible App, redacted argv, cwd, cumulative/window CPU and disk bytes, Resident, Footprint and lifetime peak, cumulative energy, threads, open files and sockets. Reverse names share one two-second deadline; failed lookups retain the remote IP. Another user's Process is ps-only without root. Root also reads filesystem activity over the window. Every optional denied/missing reading is null with a `skipped` reason and retry line. `hostvitals process --help` documents every key, observation limit and privilege rule.

The effect crate owns native reads, CLI execution and JSON. The policy crate has no I/O and every function passes Flux. Real-binary integration tests substitute a cargo example for each Apple CLI on PATH. Build that stand-in with `cargo build --example probe-cli` before running an individual integration test; the gate builds it automatically.

Memory reads `vmmap -summary`, a wide non-coalesced region report, and `footprint`'s bytes-format total. Each section is available or explicitly skipped with a reason and retry command; an inaccessible vmmap never hides a readable Footprint. Largest regions follow vmmap's dirty-plus-swapped size ranking. Reports are sequential observations, and vmmap's rounded sizes retain their reported precision after conversion to bytes. Pure parser tests use captured Apple reports plus synthetic swapped, IOKit and IOSurface regions. They cover malformed and truncated reports, checked size arithmetic, clean memory, malloc zones and ranking.

For deterministic native reads, set `HOSTVITALS_PROBE_FIXTURES` to a directory containing `host.json`, `rusage.json`, `libproc.json`, `ioreport.json` and `responsibility.json`. The host fixture has `macos_version`, `arch` and numeric `euid`. Each native fixture is `{"status":"available","data":{...}}` with the fields documented by `hostvitals doctor --help`, or `{"status":"unavailable","reason":"..."}`. Doctor warns on stderr and labels the answer `source: "fixtures"`; malformed or missing native fixtures never fall back to live reads. CLI stand-ins use one JSON state file per tool (`exit_code`, `stdout`, `stdout_readings`, `stderr`, `calls`, `delay_ms`): each call uses its corresponding `stdout_readings` entry when present, otherwise `stdout`. They never replace the process's own effective user in a live invocation. Native fixtures apply to doctor, now and process; memory reads the CLIs on PATH.

The `now` integration tests use the same fixture source with `now-host-0.json` and `now-host-1.json` for the two host readings. Their `data` has `euid`, `cpu_ticks` (user, system, idle, nice), `logical_cores`, `physical_cores`, `load_average`, and `memory` with the output fields described by `hostvitals now --help`. Per-process files are `now-rusage-<pid>.json` (the doctor's rusage fields) and `now-responsibility-<pid>.json` (`pid`, `app_pid`). The `ps` and `nettop` stand-ins' `stdout_readings` arrays supply successive snapshots; actual monotonic time still measures each interval. Nettop CSV starts with `,bytes_in,bytes_out,` and has rows such as `root daemon.10,9000000000,8000000000,`; a header alone reports no sockets. The 48 GiB host fixture retains the 13-day root `fseventsd`, nearly full swap, and 31 small `claude` processes whose responsible App totals 4.1 GiB.

Network reads use `nettop -L 1 -n -P -x -J bytes_in,bytes_out` twice, with no DNS lookup or remote requests. `host.network.window_seconds` is the actual monotonic interval used by every `network.bytes_in_per_second` and `network.bytes_out_per_second` rate. Host throughput sums TCP and UDP process accounting across all interfaces, including loopback and proxy accounting; it is not a physical-link rate. Rankings cover Processes and Apps in both directions. Changed identities, one-sided readings and regressed counters stay null, propagate into App and host totals, and are explained in `skipped`. No sockets at either snapshot means zero for a stable Process; sockets entirely between snapshots can be missed. A failed or malformed nettop report skips network while retaining CPU and memory. Tests cover root traffic, responsible App sums, different incoming/outgoing rankings, column order, comma/dot names, delayed reads, 64-bit counters, null propagation, malformed reports and missing or failing nettop.

Process fixtures add `process-owner.json` (an available numeric effective UID), `process-rusage-0.json` and `process-rusage-1.json` (doctor's rusage fields), `process-task.json` (pid, resident_bytes, threads), and `process-app.json` (pid, app_pid). `process-arguments.bin` is a **synthetic** KERN_PROCARGS2 buffer: native-endian i32 argc, NUL-terminated executable path, zero padding, argc NUL-terminated arguments, then optional synthetic environment sentinels. Never record real argument buffers or environments as fixtures. The native reader bounds and sanitizes these fixtures through the same parser as live arguments; missing/malformed fixtures never fall back to live reads. Process tests cover binary output and errors, real argv and sockets, redaction properties, shared DNS timeout, process identity churn, root event parsing and non-root privilege skips. Native fixtures now apply to process as well as doctor and now; memory still reads only CLIs on PATH.
