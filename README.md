# hostvitals

A read-only macOS agent CLI for host and process observations. Start with `hostvitals --help`, then `hostvitals doctor`; `hostvitals help all` opens the complete manual. Doctor inventories observation capabilities. `hostvitals now --seconds 3 --top 10` judges and measures host CPU, memory, network and energy, every user's processes, responsible App totals and ten rankings in one window. Other users' CPU, resident memory, network bytes and energy impact are included without root; footprint and GPU-time reads that need elevation are explicitly skipped. `hostvitals memory <pid> [--top 15]` explains one Process's Footprint, region kinds, malloc zones and largest regions; `hostvitals memory --help` documents every output key and the size ranking.

`now` serializes `findings` before the raw sections. Each Finding names its stable rule, host or Process subject, measured values, threshold and comparison, and a next command. Process subjects preserve PID and start time. The pure rules cover memory pressure, swap use, a Process's Resident share of host memory and sustained CPU across the actual Window; `hostvitals now --help` derives their thresholds from the same code and documents every field. A healthy observation has `findings: []`. Every final Process is judged regardless of `--top`; summing Processes into Apps adds no extra findings for these rules. Missing CPU baselines and zero denominators yield no ratio finding. Suggestions let the caller inspect memory Rankings again, run `hostvitals memory PID` for Resident, or run `hostvitals profile PID` for CPU; `now` never executes them.

Install on macOS arm64 or x86_64:

```sh
brew install sunfmin/tap/hostvitals
```

For an AI agent, install the skill that points to the tool's help:

```sh
npx skills add sunfmin/hostvitals
```

Some measurements need root and are skipped without it. hostvitals never runs `sudo` itself; `hostvitals doctor` reports the observation capabilities here and the fixes for anything missing.

Build locally with `cargo build --locked -p hostvitals` on macOS arm64 or x86_64. Stable Rust builds the binary; the pinned nightly runs the verification gate. `./gate.sh` is the same gate locally and in CI: format, Flux alone (no trusted or ignored functions), clippy, release packaging checks, then nextest. The checker versions and nightly live in `Cargo.toml`; `./verify.sh` rejects mismatches with installation instructions. Install nextest with `brew install cargo-nextest`.

`hostvitals process <pid> [--seconds 3]` observes one Process: identity and responsible App, redacted argv, cwd, cumulative/window CPU and disk bytes, Resident, Footprint and lifetime peak, cumulative energy, threads, open files and sockets. Reverse names share one two-second deadline; failed lookups retain the remote IP. Another user's Process is ps-only without root. Root also reads filesystem activity over the window. Every optional denied/missing reading is null with a `skipped` reason and retry line. `hostvitals process --help` documents every key, observation limit and privilege rule.

The effect crate owns native reads, CLI execution and JSON. The policy crate has no I/O and every function passes Flux. Real-binary integration tests substitute a cargo example for each Apple CLI on PATH. Build that stand-in with `cargo build --example probe-cli` before running an individual integration test; the gate builds it automatically.

`hostvitals profile <pid> [--seconds 5] [--top 10]` samples call stacks, ranks exclusive hot paths with counts and shares, combines top frames, and says when the Process was mostly waiting. Counts cover all thread samples, including sleeping threads; shares are not CPU percentages. Recognized kernel waits remain in top frames and the share denominator but are excluded from hot paths. A Process ending during sampling still returns useful observations. Denial is skipped with the caller's sudo retry line.

Profile retains sample's full output in a distinct private directory under `$TMPDIR/hostvitals/` and returns `report_path`. Its summary uses those same bytes; progress output is never a second observation. Reports are owner-only (0600) inside owner-only directories (0700), remain readable after exit, and may be purged by macOS. Remove the returned report's containing profile directory when finished. Other commands, including doctor, save no reports. `hostvitals profile --help` documents every JSON key, ranking semantics, partial results and collection limits.

The gate checks the actual pure Profile parser and its [counted-call-graph regressions](docs/verification/flux-loop-joins.md). That note records the pinned checker's loop-join defect and the verified helper extraction used by the parser; runtime tests and Flux share the product source.

Memory reads `vmmap -summary`, a wide non-coalesced region report, and `footprint`'s bytes-format total. Each section is available or explicitly skipped with a reason and retry command; an inaccessible vmmap never hides a readable Footprint. Largest regions follow vmmap's dirty-plus-swapped size ranking. Reports are sequential observations, and vmmap's rounded sizes retain their reported precision after conversion to bytes. Pure parser tests use captured Apple reports plus synthetic swapped, IOKit and IOSurface regions. They cover malformed and truncated reports, checked size arithmetic, clean memory, malloc zones and ranking.

For deterministic native reads, set `HOSTVITALS_PROBE_FIXTURES` to a directory containing `host.json`, `rusage.json`, `libproc.json`, `ioreport.json` and `responsibility.json`. The host fixture has `macos_version`, `arch` and numeric `euid`. Each native fixture is `{"status":"available","data":{...}}` with the fields documented by `hostvitals doctor --help`, or `{"status":"unavailable","reason":"..."}`. Doctor warns on stderr and labels the answer `source: "fixtures"`; malformed or missing native fixtures never fall back to live reads. CLI stand-ins use one JSON state file per tool (`exit_code`, `stdout`, `stdout_readings`, `stderr`, `calls`, `delay_ms`, `report`): each call uses its corresponding `stdout_readings` entry when present, otherwise `stdout`. The sample stand-in writes `report` to the requested report file (falling back to stdout when report is absent), while doctor still uses /dev/null. They never replace the process's own effective user in a live invocation. Native fixtures apply to doctor, now and process; memory and profile read the CLIs on PATH.

The `now` integration tests use the same fixture source with `now-host-0.json` and `now-host-1.json` for the two host readings. Their `data` has `euid`, `cpu_ticks` (user, system, idle, nice), `logical_cores`, `physical_cores`, `load_average`, and `memory` with the output fields described by `hostvitals now --help`. Per-process files are `now-rusage-<pid>.json` (the doctor's rusage fields) and `now-responsibility-<pid>.json` (`pid`, `app_pid`). The `ps` and `nettop` stand-ins' `stdout_readings` arrays supply successive snapshots; actual monotonic time still measures each interval. Nettop CSV starts with `,bytes_in,bytes_out,` and has rows such as `root daemon.10,9000000000,8000000000,`; a header alone reports no sockets. The 48 GiB host fixture retains the 13-day root `fseventsd`, nearly full swap, and 31 small `claude` processes whose responsible App totals 4.1 GiB.

That historical fixture produces exactly three Findings: pressure, swap use and `fseventsd` Resident. Their displayed percentages follow the fixture's byte counts. Further binary scenarios cover healthy output, App sums without extra findings, Processes outside Rankings, delayed collection using the actual Window, a usable profile suggestion, and absent/reused/regressed CPU baselines. Policy tests cover exact threshold boundaries, zero denominators and maximum integer inputs; Flux checks the integer comparisons without percentage rounding.

Network reads use `nettop -L 1 -n -P -x -J bytes_in,bytes_out` twice, with no DNS lookup or remote requests. `host.network.window_seconds` is the actual monotonic interval used by every `network.bytes_in_per_second` and `network.bytes_out_per_second` rate. Host throughput sums TCP and UDP process accounting across all interfaces, including loopback and proxy accounting; it is not a physical-link rate. Rankings cover Processes and Apps in both directions. Changed identities, one-sided readings and regressed counters stay null, propagate into App and host totals, and are explained in `skipped`. No sockets at either snapshot means zero for a stable Process; sockets entirely between snapshots can be missed. A failed or malformed nettop report skips network while retaining CPU and memory. Tests cover root traffic, responsible App sums, different incoming/outgoing rankings, column order, comma/dot names, delayed reads, 64-bit counters, null propagation, malformed reports and missing or failing nettop.

Energy impact comes from top's second `PID POWER` sample for every user. Process and App `energy_impact` values have `processes_by_energy` and `apps_by_energy` Rankings; missing process scores propagate into App totals. Battery reports charge, charging state, power source and time estimate, or explicitly no battery. Thermal reports CPU speed limits and adds a host Finding below full speed. IOReport reads component watts and GPU active share without root, with its own actual sampling interval. Per-process `gpu_time_ms` uses root-only powermetrics tasks and its reported elapsed interval; non-root observations skip it with the exact sudo retry line. All collectors finish before the command exits, and a failed energy source preserves the others. The full field and privilege contract is in `hostvitals now --help`.

An IOReport channel with zero accumulated energy in both raw samples cannot establish a readable counter; it is null with a reason, while a zero delta at a positive baseline is an observed idle zero. This matters on the tested macOS 27 host, where CPU and ANE counters stayed zero while GPU Power remained readable. Doctor now checks for accumulated CPU energy as well as channel discovery and sampling, so it identifies this degradation. This conservative rule can also skip an unused channel. Fixtures can reproduce both unreadable counters and valid idle readings.

Energy fixtures add `now-power.json`: an available reading's data has `window_seconds`, `energy` items (`name`, `unit`, signed `value` delta, optional `counter_before` and `counter_after`), and `gpu_states` pairs of state name and signed residency delta. Omitted absolute counters denote already validated fixture deltas; live reads always supply both. An unavailable reading skips Power alone. The shared `top`, `pmset` and `powermetrics` CLI stand-ins supply their actual text formats. Scenarios cover root privilege checks, no battery and no estimate, speed-limit findings, unit conversion, multi-die totals, GPU residency, identity churn, incomplete App scores, malformed reports and independent source failures.

Process fixtures add `process-owner.json` (an available numeric effective UID), `process-rusage-0.json` and `process-rusage-1.json` (doctor's rusage fields), `process-task.json` (pid, resident_bytes, threads), and `process-app.json` (pid, app_pid). `process-arguments.bin` is a **synthetic** KERN_PROCARGS2 buffer: native-endian i32 argc, NUL-terminated executable path, zero padding, argc NUL-terminated arguments, then optional synthetic environment sentinels. Never record real argument buffers or environments as fixtures. The native reader bounds and sanitizes these fixtures through the same parser as live arguments; missing/malformed fixtures never fall back to live reads. Process tests cover binary output and errors, real argv and sockets, redaction properties, shared DNS timeout, process identity churn, root event parsing and non-root privilege skips. Native fixtures now apply to process as well as doctor and now; memory still reads only CLIs on PATH.
