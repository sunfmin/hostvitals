# hostvitals

A read-only macOS agent CLI for host and process observations. Start with `hostvitals --help`, then `hostvitals doctor`; `hostvitals help all` opens the complete manual. Doctor inventories observation capabilities. `hostvitals now --seconds 3 --top 10` measures host CPU and memory, every user's processes, responsible App totals and four rankings in one window. Other users' CPU and resident memory are included without root; footprint reads that need elevation are explicitly skipped. `hostvitals memory <pid> [--top 15]` explains one Process's Footprint, region kinds, malloc zones and largest regions; `hostvitals memory --help` documents every output key and the size ranking.

Build locally with `cargo build --locked -p hostvitals` on macOS arm64 or x86_64. Stable Rust builds the binary; the pinned nightly runs the verification gate. `./gate.sh` is the same gate locally and in CI: format, Flux alone (no trusted or ignored functions), clippy, then nextest. The checker versions and nightly live in `Cargo.toml`; `./verify.sh` rejects mismatches with installation instructions. Install nextest with `brew install cargo-nextest`.

The effect crate owns native reads, CLI execution and JSON. The policy crate has no I/O and every function passes Flux. Real-binary integration tests substitute a cargo example for each Apple CLI on PATH. Build that stand-in with `cargo build --example probe-cli` before running an individual integration test; the gate builds it automatically.

Memory reads `vmmap -summary`, a wide non-coalesced region report, and `footprint`'s bytes-format total. Each section is available or explicitly skipped with a reason and retry command; an inaccessible vmmap never hides a readable Footprint. Largest regions follow vmmap's dirty-plus-swapped size ranking. Reports are sequential observations, and vmmap's rounded sizes retain their reported precision after conversion to bytes. Pure parser tests use captured Apple reports plus synthetic swapped, IOKit and IOSurface regions. They cover malformed and truncated reports, checked size arithmetic, clean memory, malloc zones and ranking.

For deterministic native reads, set `HOSTVITALS_PROBE_FIXTURES` to a directory containing `host.json`, `rusage.json`, `libproc.json`, `ioreport.json` and `responsibility.json`. The host fixture has `macos_version`, `arch` and numeric `euid`. Each native fixture is `{"status":"available","data":{...}}` with the fields documented by `hostvitals doctor --help`, or `{"status":"unavailable","reason":"..."}`. Doctor warns on stderr and labels the answer `source: "fixtures"`; malformed or missing native fixtures never fall back to live reads. CLI stand-ins use one JSON state file per tool (`exit_code`, `stdout`, `stdout_readings`, `stderr`, `calls`, `delay_ms`): each call uses its corresponding `stdout_readings` entry when present, otherwise `stdout`. They never replace the process's own effective user in a live invocation. Native fixtures apply to doctor and now; memory reads the CLIs on PATH.

The `now` integration tests use the same fixture source with `now-host-0.json` and `now-host-1.json` for the two host readings. Their `data` has `euid`, `cpu_ticks` (user, system, idle, nice), `logical_cores`, `physical_cores`, `load_average`, and `memory` with the output fields described by `hostvitals now --help`. Per-process files are `now-rusage-<pid>.json` (the doctor's rusage fields) and `now-responsibility-<pid>.json` (`pid`, `app_pid`). The `ps` stand-in's `stdout_readings` array supplies successive snapshots; actual monotonic time still measures the window. The 48 GiB host fixture retains the 13-day root `fseventsd`, nearly full swap, and 31 small `claude` processes whose responsible App totals 4.1 GiB.
